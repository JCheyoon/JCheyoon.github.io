# 초안 작성

규칙은 `.claude/rules/content.md`를, frontmatter는 `docs/SPEC.md` §5를 따른다.
파일은 블로그 MCP 서버(`cheyoon-blog`)의 도구로 만든다(SPEC §9.4). 도구가 draft 상태와 규칙을 강제한다.
MCP 도구를 쓸 수 없으면 멈추고, 이 저장소에서 Claude Code를 열어 `/mcp`로 `cheyoon-blog`를 연결하라고 안내한다. 파일을 직접 만들지 않는다.

## 입력
다음 네 가지가 모두 필요하다. 빠진 것이 있으면 먼저 질문한다.
- 주제
- 대상 독자
- 검색 의도
- 작성자의 경험이나 메모

## 절차
1. `src/content/posts/`에서 같은 주제의 글을 찾는다.
   겹치는 글이 있으면 멈추고 그 글을 보강하자고 제안한다.
   - 글 목록은 `list_posts`로 본다.
2. 템플릿을 제안한다(SPEC §5.7).
   - `list_templates`의 `when`과 주제·메모를 비교해 기본 템플릿 1개와, 필요하면 선택 블록(트러블슈팅, 버그 해결)을 고른다.
   - 고른 이유를 한두 문장으로 말하고, 대안이 있으면 함께 말한다. 맞는 템플릿이 없으면 자유 형식을 제안한다.
3. 개요를 보여 주고 확인을 받는다. 템플릿을 골랐으면 그 섹션 순서를 따른다.
   첫 문단에서 검색 의도에 바로 답하도록 구성한다. 제목은 본문과 일치하고 과장하지 않는다.
   안내 상자는 `> [!TIP] 제목` 문법을 쓴다(SPEC §5.6).
4. slug는 영문으로 제안하고 사용자 확인을 받는다.
5. `create_draft`로 초안을 만든다.
   - 본문을 써서 `body`로 넘긴다. 템플릿을 골랐으면 그 섹션과 `<!-- 안내: … -->` 주석을 살려 채운다.
   - `status`, `ai_assisted`, `created_at`은 도구가 정한다.
   - 거부되면 이유를 사용자에게 보여 주고 고친다.
6. `check_post`로 검사 결과를 확인한다.
7. 표시를 남긴다.
   - 경험이 필요한 자리: `[경험 추가 필요: 무엇]`
   - 출처가 없는 사실: `[출처 확인 필요]`
8. 이미지가 필요하면 자리를 표시하고, 파일은 작성자가 넣게 한다(SPEC §5.4).
   - 예: `[경험 추가 필요: 실행 결과 스크린샷 → src/assets/posts/<slug>/result.png]`
   - 이미지를 만들거나 외부 이미지 주소를 쓰지 않는다.

## 하지 않는 것
- 경험, 사례, 수치를 지어내기
- 출처 없는 수치 쓰기
- 다른 글의 문장 옮기기
- 한 번에 2편 이상 만들기
- status 바꾸기

## 출력
- 고른 템플릿과 선택 블록
- 파일 경로
- 남은 `[...필요]` 표시 목록
- 작성자가 보완할 일 3가지 이내
